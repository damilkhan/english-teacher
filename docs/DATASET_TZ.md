# ТЗ: дообучение LoRA для EnglishTeacher (Verbot)

Проект: локальный ИИ-преподаватель английского. Ученик A2, американский английский.
Цель обучения: научить модель **говорить в роли внутри сцены** (официант, продавец)
коротко и живо, правильно **понимать** реплику ученика и **держать роль**.

## 1. Модель: БАЗА = та, которую реально запускаем

⚠️ **Поправка 03.11.2026 (ночь).** В первой версии этого ТЗ стоял
`Qwen/Qwen2.5-7B-Instruct`. Это противоречило железу ученика, и противоречие
поймал ученик.

Факты (замер 03.11.2026, llama-bench, tg32):

| Модель | GPU (Vulkan, RX 6600 8 ГБ) | CPU |
|---|---|---|
| Gemma-4-E4B Q4_K_M (7,52B) | **51,68 ток/с** | — |
| Qwen2.5-7B Q4_K_M (7,62B) | 2,95 ток/с | 6,65 ток/с |

Qwen на CPU быстрее, чем на GPU: сборка llama.cpp под Vulkan считает Qwen2
неверно. **Локально Qwen запускать нельзя.** А LoRA привязана к базе: обучили бы
Qwen — дома запускать нечего, работа в мусор.

**Правило проекта:** обучаем ТОЛЬКО ту модель, которую потом запускаем.

**База = Gemma-4-E4B** (та же, что в бою:
`models/gemma/Gemma-4-E4B-Uncensored-HauhauCS-Aggressive-Q4_K_M.gguf`).

Минус честно: Gemma-4-E4B — MatFormer (per-layer embeddings), готового рецепта
SFT мало, возможны правки в скрипте обучения. Плюс: скорость 51,7 ток/с и зрение
остаются, ничего в приложении менять не надо.

**Порядок работы (решения ученика 110–112):**
1. Сначала **промпт на вселенной** (`data/train/universe_a2.json` → системный
   промпт), замер на 10 живых фразах. Норма — 80 %. Тогда LoRA нужна только для
   остатка (20 %).
2. LoRA — только если промпта не хватило. База — Gemma-4-E4B.
3. Qwen2.5-7B — **не раньше**, чем у друга/у нас появится рантайм, где Qwen
   быстрый. Файл `models/qwen2.5-7b-q4km.gguf` лежит, решение отложено.

Для обучения нужен **HF-чекпойнт базы в bf16** (~15 ГБ для 7,5B), а не GGUF:
в квантованный GGUF LoRA не вливается.

## 2. Данные

Всё лежит в `data/train/`, собрано **кодом** из описания мира
(`universe_a2.json`) скриптами `tools/build_universe.py` +
`tools/build_dataset.py`. Формат — chat-format JSONL, одна строка = один пример.

| Файл | Строк | Задача |
|---|---|---|
| `classify.jsonl` | 4985 | реплика ученика -> `{"intent","item","count"}` |
| `react.jsonl` | 1937 | реакция персонажа, одна фраза <= 12 слов |
| `roleplay.jsonl` | 90 | многоходовой диалог (system = персонаж) |
| `heldout.jsonl` | 183 | **НЕ УЧИТЬ.** Отложено для замера, другие шаблоны |

Пересобрать: `python tools/build_universe.py && python tools/build_dataset.py`
(детерминировано, seed=20261103).

## 3. Гиперпараметры (стартовая точка)

```
base          HF-чекпойнт Gemma-4-E4B (bf16), НЕ gguf
method        LoRA (SFT)
r             16
lora_alpha    32
lora_dropout  0.05
target_modules проверить по архитектуре (MatFormer: слои внимания + MLP)
lr            1e-4 (cosine, warmup 3%)
epochs        2
batch         2 x grad_accum 8 (эффективно 16)
max_seq_len   2048
bf16          True
```

Время: ~40–60 мин на 1x A100 40GB (оценка для 7B-класса, не замер).
На 24GB — `load_in_4bit`.
Если рецепт Gemma не заводится — писать об этом, а не подменять базу на Qwen.

## 4. Что вернуть

1. **merged bf16** (LoRA слита в базу) — safetensors.
2. **GGUF Q4_K_M** — `llama.cpp/convert_hf_to_gguf.py` + `llama-quantize`.
3. Лог обучения (loss по эпохам) + какой рецепт/версия фреймворка использованы.

Файлы — в `models/gemma-lora/`.
⚠️ После слияния **обязательно** замерить скорость gguf: MatFormer может
просесть. Если просядет ниже 20 ток/с — LoRA не годится для боя.

## 5. Как проверять (не на глаз)

1. `heldout.jsonl` (183 фразы, модель их НЕ видела): `tools/eval_lora.py`
   считает точность намерения и предмета. Сравнение: до / после.
2. Живой прогон 10 фраз из Шага 1 (на тех же, что мерили промпт) — чтобы
   сравнение было честным: промпт vs промпт+LoRA.

## 6. Отдельные сессии (важно)

Не мешать задачи в один прогон. Обучать **три отдельные LoRA**:
1. `classify` — только `classify.jsonl` (понимание).
2. `react` + `roleplay` — вместе (манера речи и роль).
3. Позже `correct` — разбор ошибок (данные ещё собираются).

Все три — на одной базе (Gemma-4-E4B), иначе на дом не встанут.

## 7. Чего НЕ ждать

- Модель не станет знать больше английского (она его уже знает).
- Факты (цены, состав меню) всё равно берутся кодом — модель может соврать.
  Правило: **факты — код, речь — модель.**
- Шаг диалога держит код, а не модель.
- LoRA не спасёт от дыр в описании мира: сначала вселенная и промпт.
