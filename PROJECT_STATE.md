## 1. Что это

Локальный ИИ-преподаватель английского «Джейн». GUI на **CustomTkinter**, модель —
локальный **llama.cpp** (Gemma-4-E4B), речь — **faster-whisper** (STT) и **edge-tts** (TTS).
Всё на CPU, VRAM не трогаем.

**Главная цель — прокачка РАЗГОВОРНОГО английского (speaking), а не письма.**
Поэтому: push-to-talk микрофон, голосовые уроки, робот-персонаж с живым лицом,
погружение в английский.

### Память модели (контекст) — замер и запас

`SERVER_CONTEXT = 8192` (было 4096). Замер по `/tokenize` самой модели:

системный промпт **1142** токена, RAG-заметки (2 чанка) **1037**, слова этапа C

**136**, история (6 реплик) **121** → вход ~**2323** токена + 400 на ответ =

**2723 из 4096 (66 %)**. При 8192 тот же запрос занимает 33 % — запас вдвое.

Модель обучена на 131 072, память почти не растёт: при 8192 сервер берёт те же

~3.1–3.4 ГБ (замер).



**Сервер НЕ обрезает длинный запрос сам** — он отвечает ошибкой

`400 exceed_context_size_error` с числами. Раньше это превращалось в «Error: 400»

и ученик видел заглушку «Sorry, I can't respond.» без причины. Теперь:



- `llm_client` распознаёт переполнение (`CONTEXT_PREFIX`, `is_context_error`)

  и говорит числами: «запрос (12009 токенов) больше памяти модели (8192)»;

- `ChatController._request` при переполнении ПОВТОРЯЕТ запрос с короткой

  историей (`CONTEXT_RETRY_LINES = 2` строки) и без RAG

  (`CONTEXT_RETRY_RAG = True`) — ученик получает обычный ответ;

- если и повтор не помог — понятная фраза («Ответ не уместился в память

  модели даже с короткой историей…»), а не заглушка;

- обычный путь не менялся: один запрос, промпт тот же (правило §10).



Проверки: `tests/test_context_limit.py` (6 разделов).



## 6. Как идёт диалог

```
ВВОД
 ├─ текст → InputBar
 └─ голос → push-to-talk → audio_vad → stt_engine → RecordingController
                      ↓
ЕСТЬ ЛИ КИРИЛЛИЦА? (translate.has_cyrillic)
 ├─ ДА и TRANSLATE_ENABLED → hint_bar (перевод), в чат НЕ пишем ← стоп
 └─ НЕТ → в чат «Вы», дальше
                      ↓
ChatController.send() → фоновый поток
 ├─ build_system_prompt(mode, profile, lang, level, student,
 │                      context=RAG, plan=Планировщик, lesson=,
 │                      now=datetime.now(), variety=True, english_only=)
 ├─ LLMClient.complete(messages) → /v1/chat/completions
 ├─ on_message → чат
 ├─ on_response → TTS + лицо
 │    mood.plan_reply делит ответ на куски по настроению → tts.speak(parts=…)
 │    → на начале звука КАЖДОГО куска приходит колбэк → лицо меняет эмоцию
 └─ on_analysis → Аналитик → info_bar + reactions (3 промаха)
                      ↓
TTS: split_by_language → голос по языку (Ava en / Светлана ru)
     → стриминг mp3→PCM→sounddevice → уровень громкости
     → эквалайзер + рот робота
```

**Порядок «Джейн говорит первой»:** `ChatController.begin_lesson()` отправляет
служебную реплику-затравку. Она **не** идёт ни в разбор Аналитика, ни в прогресс,
ни в историю (флаг `_opening`).

## 7. Лицо робота

**Принцип:** тело — кукла (`face_empty.png`), лицо — сменные наклейки
(слои глаз и рта). Все слои выгружены **по общему холсту 661×377** — накладываются
без подгонки.

### Состояния (`character_face.STATES`)
`idle`, `listening`, `thinking`, `speaking`, `happy`, `smile`, `sad`,
`surprised`, `scorn`, `angry` + «говорящие» `speak_happy`, `speak_sad`,
`speak_surprised`, `speak_thinking`, `speak_story` + `story_end`.

### Поведение
| Что | Параметр |
|---|---|
Моргание | `BLINK_DURATION=0.05`, `SHUT=0.08`, `BLINK_FADE=0.02`, `BLINK_MAX_VISIBLE=0.14` |
Взгляд по сторонам | пауза 1.6–3.4 с, удержание `0.75`, жёсткий предел `1.1` |
Смена глаз | `EYES_FADE=0.05` (короткий, иначе кадры с «прищуром») |
Рот в речи | `MOUTH_RATE=6.2` слога/с, три ступени по громкости |
Кивок | `NOD_DEPTH=6` px, после моргания и на паузах речи ученика |
Конец рассказа | `STORY_END`: закрытые глаза **3 с**, потом покой
Смена эмоции | по КОЛБЭКУ из `tts.py` — ровно на начале звука куска (не по часам)

### Жёсткие правила (иначе ученик видит «зажмурилась»)
- **`SQUINT_EYES = (eyes_closed, eyes_closed_shut, eyes_smile, eyes_scorn)`** —
  эти слои ВЫГЛЯДЯТ закрытыми. В «говорящих» состояниях их использовать нельзя.
- `eyes_smile` — линия 19 px, `eyes_scorn` — 24 px: на теле это прищур.
- Смена эмоции **сбрасывает** моргание/взгляд/кивки (иначе «замерзает»).
- Пока идёт `play_sequence`, обычный `set_state` не применяется.

### Сценарий «три промаха → справился» (`reactions.py`)
3 неудачи подряд → верный ответ → **удивление 1.5 с → улыбка 2.4 с** → возврат.
«Непонятный ответ» (`ok=None`) серию не рвёт и не увеличивает.

## 8. Карта прогресса и занятия

### Данные
`knowledge_base/curriculum.json`: **13 локаций** (A0 → C1), по 9 блоков в каждой,
по **3 урока + ПРОВЕРКА** в блоке: **468 уроков** (117 проверочных).
Собирается скриптом `tools/build_curriculum.py` (там же темы и названия).
Размер картинки локации — 1248×832 (`assets/map/<id>.jpg`).
Порядок точек — **по полю `number`** (по тропе карты, старт — низ-слева).

| Уровень | Локации |
|---|---|
| A0 | Пустыня |
| A1 | Лесная тропа, Речная долина |
| A2 | Городские улицы, Горный перевал |
| B1 | Морской берег, Ночной рынок, Северное сияние |
| B2 | Заброшенные руины, Вулкан, Ледяные пещеры |
| C1 | Небесные острова, Космическая станция |

**id блоков и уроков уникальны во всём плане.** Учебные номера повторяются
(в каждом блоке есть «1.1»), и раньше карта съедала повторы как дубликаты —
читалась только первая локация. Теперь id вида `forest/1.1`, а в поле `code`
лежит короткий номер для экрана («1.1»). Исключение — **«Пустыня»**: её уроки
остались с простыми id (`1.1`, `1.2` …), чтобы не потерять уже пройденное
в профиле ученика.

### Состояния
`locked` / `unlocked` / `completed`. Прохождение **линейное**: первый урок открыт
всегда, следующий — после предыдущего; точка открыта, если предыдущая пройдена.

### Занятие
- Типы: `speaking` (только голос), `chat` (только текст), `listening`
  (голос + «режим рассказа»: Джейн рассказывает историю, ученик пересказывает).
  `mixed` в UI не используется.
- `LESSON_REPLY_TARGET = 12` — реплик ученика до автозавершения.
- Ранний выход («Выйти») — урок **не засчитывается**, разбор уже записан.
- Урока нет без микрофона; если Whisper грузится — урок ждёт и стартует сам.

### Кто выбирает урок (этап B+ — СДЕЛАНО)

«Следующий урок» = первый **непройденный** по порядку карты
(`progress_map.next_lesson(profile)`). Джейн начинает его **САМА**, как только
ученик что-то сказал — голосом или текстом, включая русское «привет»
(проверка стоит ДО переводчика, грабли №28). Вопроса «Начнём урок 1.2?
Да / Позже» НЕТ (решение §14.5).

Порядок запуска: профиль → модель → тест уровня → повторение слов → **урок**.
Автозапуск взводится после окна повторения и когда модель готова; одна попытка
за запуск; любой урок, начатый с карты, его гасит. Реплика ученика уходит в
первую реплику урока (`begin_lesson(student_text=…)`), поэтому приветствие не
теряется; в чате видно «🎓 Начинаем Урок 1.1 …» и «📚 По плану дальше — этот
урок». Если урок нельзя начать (нет микрофона) — видна причина, а текст идёт
обычным путём; если Whisper ещё грузится — урок ждёт и стартует сам
(`_pending_lesson`). Вся карта пройдена → «🎉 Вся карта «Пустыня» пройдена!».
Выключатель — `LESSON_AUTO_START` в `config.py`.

Кнопка `📚 Повторить слова` в окне блока открывает повторение в любой момент,
но автозапуск урока НЕ взводит (ученик пришёл с карты, а не поздоровался в чате).

### Локации: порядок и переключатель (СДЕЛАНО)

Локации открываются **по очереди**: первая всегда, следующая — когда предыдущая
пройдена целиком (`get_location_state` / `is_location_completed`). Состояние
блока и урока учитывает локацию: в закрытом мире всё закрыто (раньше первый
блок «Лесной тропы» горел зелёным, хотя ученик туда ещё не дошёл).



Закрытые локации можно **посмотреть** — так видно, куда идём: стрелки ◀ ▶ на

карте (`switch_location`), а подпись говорит «🔒 Закрыто · сначала пройди

«Пустыня»». Пока картинки локации нет, на её месте аккуратная заглушка

«🗺 Название · уровень · карта скоро» — карта не выглядит сломанной.



Карта открывается на **первой непройденной** локации (`first_open_location`),

а не всегда на «Пустыне».



### Проверочные занятия (СДЕЛАНО)

Каждый блок заканчивается **проверкой** (тип урока `check`): Джейн не учит
новому, а спрашивает по пройденному блоку и в конце говорит, что закрепилось,
а что надо повторить. Занятие только голосом (цель — говорение), длиннее
обычного урока: `LESSON_CHECK_REPLY_TARGET = 16` против `LESSON_REPLY_TARGET = 12`.
Блок считается пройденным только вместе с проверкой.

## 9. Экспресс-переводчик

Ученик пишет по-русски → над полем ввода появляется английский вариант.
**Это не отправка:** ученик сам решает (вставить, послушать, сказать вслух).

- Одно слово → до **трёх разных значений** с примерами.
- Фраза → одна строка.
- Кнопки: **↺** вставить в поле **в место курсора**, **✕** закрыть.
- **Озвучка — кликом по слову** (решение ученика, `TTS` не нужен): раньше
  кнопка 🔊 читала только ПЕРВОЕ значение, остальные послушать было нельзя.
  Теперь каждое значение нажимается отдельно — клик по английскому слову
  читает слово, клик по примеру — пример. При наведении мыши слово
  подсвечивается (фон + яркий текст + курсор-рука), поэтому видно, что на
  него можно нажать. Служебные строки («Перевожу…») не нажимаются.
  То же для фразы и для вердикта сверки произношения (нажатие читает эталон).
  Высота полосы не выросла: 3 значения = 78 px, как и раньше.
- Кнопки «Отправить» **нет** — следующий шаг должен быть речью (push-to-talk).
- Скорость: фраза ~0.3 с, слово ~0.7 с (наша же модель). Фразник + кэш на 200.

### Сверка произношения (после подсказки)
Ученик произносит английскую фразу в микрофон → в той же полосе появляется вердикт:
| Вердикт | Что видит ученик | Что дальше |
|---|---|---|
| ✅ `good` (≥`PRON_GOOD`) | «✅ Похоже! «…»» | реплика уходит Джейн, диалог продолжается |
| 🟡 `almost` (≥`PRON_ALMOST`) | «🟡 Почти: «keys» вместо «key»» + 🔊 | в диалог **не** уходит, ученик повторяет |
| 🔁 `off` | «🔁 Попробуй ещё: …» + 🔊 | то же |
| — `unrelated` | ничего | обычный диалог (сказал своё) |

- Эталон — **последняя английская подсказка** (`hint_bar`); для одного слова
  эталоном берётся ПРИМЕР после «—» (`reference_from_hint`).
- Живёт `PRON_MEMORY_SECONDS` = 150 с; кнопка ✕ забывает эталон сразу
  (`HintBar(on_close=…)`). Кнопка ↺ (вставить) эталон НЕ трогает.
- Сравнение — по словам: артикли `a/an/the` и запинки `um/uh` ошибкой не
  считаются (Whisper их теряет); сокращения раскрываются (`I'm` → `i am`),
  числа переводятся словами. Похожесть слова внутри — посимвольно,
  `CLOSE_WORD = 0.60` (`think`/`sink` = 0.67 → «почти», `cat`/`dog` = 0).
- Пороги настраиваются в `config.py`: строже — поднять `PRON_GOOD`/`PRON_ALMOST`,
  мягче — опустить. Код править не нужно.

### Американский английский и живые слова (СДЕЛАНО 20.10.2026)

Жалоба ученика: «мне не нужен британский, слова greeting, salutation,
«it is a warm greeting» — бестолковые». Разбор показал ТРИ источника,
и ни один из них не был уроком по учебнику:

1. **Переводчик слова** (`translate.py`) на русское «привет» отдавал ТРИ
   строки — hello / greeting / salutation. Все три становились карточками
   повторения (этап A: одно значение = одна карточка), и окно повторения
   заставляло ученика говорить «a quick salutation before speaking».
   В профиле это видно дословно: `привет. → greeting`, `привет. → salutation`.
2. **Промпт Джейн** вообще не упоминал, какой вариант английского нужен —
   модель тянулась к учебниковому регистру («simple greetings»).
3. **План уроков** содержал британские написания: Colours, favourite,
   Travelling, Holidays, film, well-organised, «At the doctor's», «In the Shop».

Что сделано:

- **Промпт переводчика переписан**: только обиходный американский английский;
  синонимы прямо запрещены («SYNONYMS ARE NOT DIFFERENT MEANINGS»); книжные
  слова перечислены как запрещённые (greeting, salutation, commence,
  purchase, assist, inquire, utilize, beverage); 3 строки — максимум, а не
  цель. Проверено на живой модели: «привет» → Hey; «магазин» → store;
  «фильм» → movie; «квартира» → apartment; «ключ» → key; «ручка» → pen /
  handle (настоящие разные значения сохраняются).
- **Фильтр в коде** (`translate._trim_meanings` + список `BRITISH_OR_FORMAL`):
  со ВТОРОЙ строки выбрасываются повторы и британские синонимы (film при
  movie, flat при apartment, shop при store). Первая строка не трогается
  никогда — это самое частое значение.
- **Новый необязательный блок промпта** `USE AMERICAN ENGLISH (US)`
  (`prompt_builder.AMERICAN_ENGLISH_BLOCK`, параметр `american`): американ-
  ское написание и слова, запрет британских форм и книжных слов, правило
  «учить обиходное слово первым» (hi, а не greetings). Выключатель —
  `config.AMERICAN_ENGLISH`. Без флага промпт прежний байт-в-байт (§10).
  Флаг Британии в блоке «только по-английски» заменён на флаг США.
- **Планировщик** (`roles/planner.py`) просит американский английский и
  живую лексику: для темы приветствия — «hi», «hey», «how's it going»,
  а не «greeting».
- **План уроков пересобран** (`tools/build_curriculum.py` → curriculum.json):
  Greetings & Hello → **Saying Hi**; Colours → **Colors**; In the Shop →
  **At the Store**; Holidays & Trips → **Vacation & Trips**; favourite →
  favorite; Travelling in town → Getting around town; film → movie;
  well-organised → well-organized; At the doctor's → At the doctor.
  id и координаты точек не менялись: 13 локаций, 468 уроков, прогресс цел.
- **Слово карточки нормализуется** (`translate.normalize_word`): «привет.» →
  «привет», иначе одно слово заводило две карточки.
- **Мусор из профиля убран**: карточки `greeting` и `salutation` удалены
  (резервная копия — `profiles/user_1_progress.json.bak_before_american`),
  осталась `привет → hello`.

Проверки: `tests/test_american_english.py` (8 разделов).

### Прогрев озвучки при старте (СДЕЛАНО 19.10.2026)

Ученик услышал: «Hello, Damil!» → **долгая пауза** → остаток фразы. Причина
не в разбиении на куски, а в том, что соединение с edge-tts **холодное**
в первые секунды после запуска приложения. Замер (каждый — новый процесс):

| Запрос подряд | Время |
|---|---|
| 1-й | **7.01 с** (таймаут) или «No audio was received» |
| 2-й | 3.11 с |
| 3-й | 5.08 с |
| 4-й и далее | **1.0–1.3 с** |

Первая реплика урока приходится ровно на эти секунды. Хуже того, каждый
повтор ждал до 7 с, а `prefs[i].wait()` ждал **без ограничения** — три
попытки давали **до 26 с тишины** (воспроизведено в замере: «всего 26.0 с,
сыграно False»).

Что теперь:
- `tts.warmup()` / `tts.warmup_async()` — беззвучные запросы к edge-tts
  **при старте приложения** (рядом с `stt.preload()`), пока ученик читает
  приветствие; греются оба голоса (Ava и Светлана);
- ожидание предзагрузки перед куском ограничено `SEGMENT_WAIT_MAX = 1.5` с:
  если кусок не готов — быстрее начать поток заново, чем молчать;
- повторы загрузки ограничены бюджетом `DOWNLOAD_BUDGET = 7` с, а повтор
  начинается только если следующая попытка в бюджет успевает
  (`RETRY_DELAY` 0.6 → 0.3 с);
- поток куска ограничен `STREAM_DEADLINE = 15` с (зависшее соединение
  больше не держит воспроизведение вечно);
- неудачная загрузка запускает **повторный прогрев** в фоне (не чаще раза
  в `WARMUP_RETRY_SECONDS = 20` с), чтобы связь восстановилась сама;
- в лог пишется строка `⏱ TTS: ожидание кусков, с: [...]`, если ждали > 0.3 с.

**Замер после правки** (та же реплика со скриншота, 4 куска 1.1/3.3/2.5/3.9 с,
6 прогонов подряд): пауза между кусками **0.03 с** (это шаг звукового блока,
на слух — без паузы). Проверки: `tests/test_tts_warmup.py` (6 разделов).

### Параллельные запросы и локальный запас (СДЕЛАНО 20.10.2026)

Жалоба ученика: реплика **обрывалась** — кусок пропадал посреди фразы.
Причина не в разбиении: edge-tts эпизодически «болеет». Замер: 18 запросов
подряд дали **8 сбоёв (44%)**, а через минуту те же 18 — все успешно. При
сбое кусок выбрасывался молча, и ученик слышал обрыв.

**Что сделано:**

- `tts._download_race` — на один кусок уходит **N одновременных** запросов,
  берём первый удачный (`config.TTS_PARALLEL_JOBS = 3`). Замер на 12 живых
  фразах Джейн:

  | Режим | Успешно | Медиана | Худший случай |
  |---|---|---|---|
  | один запрос (как было) | **6 из 12 (50%)** | 2.17 с | 4.81 с |
  | три параллельных (как стало) | **11 из 12 (92%)** | **1.11 с** | 3.51 с |

- общее число попыток осталось `RETRY_ATTEMPTS`, бюджет `DOWNLOAD_BUDGET`
  тот же (зависшая сеть не держит ученика в тишине); `TTS_PARALLEL_JOBS = 1`
  возвращает прежнее поведение;
- `tts.piper_synth` / `tts._piper_play` — **локальный голос piper** для
  АНГЛИЙСКИХ кусков: когда сети нет, слово всё равно звучит. Голос лежит в
  `models/piper/en_US-amy-medium.onnx` (60 МБ, в git его нет — `models/`
  в `.gitignore`);
- `_decode_bytes_into` принимает формат (mp3 от edge-tts / wav от piper),
  `_decode_into` осталась прежней обёрткой — старые вызовы не менялись.

**Замер локального запаса** (проектный код, сеть принудительно выключена):
загрузка голоса **0.94 с**, первая фраза **1.17 с**, дальше **0.19–0.30 с**;
память ~156 МБ; WAV 22050 Гц моно. Для сравнения Chatterbox V3 на этом же
процессоре: RTF 7.18, до первого звука 21.9 с, 7 ГБ памяти — поэтому он
**отклонён** (полные замеры — `D:\TTS_Lab\REPORT.md`).

**Русского локального голоса НЕТ — решение закрыто (пользователь, 20.10.2026).**
Проверены и отклонены: piper (4 русских голоса — акцент и неверные ударения
на омографах, за́мок/замо́к), Chatterbox V3 (акцент хуже, 7 с на секунду речи),
системный `Microsoft Irina` (ru-RU уже стоит в Windows, 190 мс на фразу,
текст верный — но качество не устроило).
**Не предлагать эти варианты снова и не искать замену без прямой просьбы.**
Правило: **лучше тишина, чем неправильные ударения**. Значит при полном
отсутствии интернета английские куски звучат локально, а русские — молчат.

Проверки: `tests/test_tts_local_fallback.py` (36 проверок).

### Слова копятся сами (этап A — СДЕЛАНО)
Одиночное слово (то, что переводится через `translate_word`, до 3 значений)
**само** попадает в файл прогресса ученика — ключ `vocabulary`, рядом с
`mistakes` и `completed_lessons`. Кнопки «сохранить» нет; фразы и предложения
не сохраняются.

Одно ЗНАЧЕНИЕ = одна карточка: `word` (русское), `en`, `example`, `level`
(0..5), `next_due`, `created`/`last_ok`/`hits`/`misses`.

Лестница (`vocabulary.INTERVALS_DAYS`): 0 новая (спросить можно уже сегодня) →
1 через день → 2 через 3 дня → 3 через 7 дней → 4 через 21 день →
**5 выучено** (больше не спрашиваем).
Удачный ответ = сверка произношения дала `good` («✅ Похоже!») → +1 к уровню
той карточки, чей ПРИМЕР был эталоном. Промах (`almost`/`off`) → −1, не ниже 0,
и спросить завтра.

- Дубликаты не создаются: ключ «слово + значение», регистр не важен.
- Уже выученное слово повторным переводом **не сбрасывается**.
- Пишем через `profile_store.add_vocabulary` / `update_vocabulary_card`
  (мимо `save()`: перевод слова — не занятие, `total_lessons` не растёт).
- Вкладка «Профиль» показывает строку «Слова: всего · к повторению · выучено».
Окно «Повторение» — этап B, см. ниже.

### Окно «Повторение» (этап B — СДЕЛАНО)

Джейн открывает окно САМА при запуске: после приветствия и профиля, когда
готовы модель и распознавание; не чаще раза в день (`vocab_last_session`),
только если есть слова на сегодня и есть микрофон. Перед окном — одна строка
в чат «📚 Давай повторим N слов». Порядок запуска: профиль → модель →
тест уровня → повторение → следующий урок.

В окне ученик видит РУССКОЕ слово и английский пример с пропуском
(«Open the door with this ___.») и произносит английское значение.
Кнопки: **🎤 Запись** (нажать и держать — тот же `RecordingController`,
второй путь к микрофону не плодим), **🔊 Послушать**, **💡 Подсказка**,
**Позже**, **Дальше** и итог захода («Верно · промахи · отложено»).
Окно модальное, стиль `BlockPanel`; `grab_set` не мешает ни микрофону,
ни озвучке. Распознанный текст уходит В ОКНО (`accept_text`), а не в чат.

Правила захода (договорены, не переспрашивать):
- удачный ответ = вердикт GOOD («✅ Похоже!») → уровень +1;
- промах («🟡 Почти» / «🔁 Попробуй») → −1, не ниже 0, спросить завтра;
- **подсказка = промах** (слово не вспомнилось само); берётся ИЗ КАРТОЧКИ,
  без модели и сети — повторение идёт, пока модель ещё грузится;
- ОДИН итог на карточку за заход: первый результативный ответ двигает
  уровень, дальше можно повторять для тренировки — уровень не шевелится;
- «Позже» → без изменений, слово вернётся в следующий раз;
- сказал по-русски → это НЕ ответ: «По-английски: key» + 🔊, ждём;
- нет микрофона → окно не открывается;
- за заход — 5 слов (`VOCAB_SESSION_SIZE`).

### Кнопка «📚 Повторить слова» в окне блока (СДЕЛАНО)

Клик по точке карты → окно блока → внизу ряд «📚 Повторить слова» + «Закрыть»
(кнопка ОДНА на весь блок: повторение не привязано к уроку). Вкладку
«Профиль» не трогали — решение пользователя (§14.6).

Кнопка работает ВСЕГДА: правило «не чаще раза в день» и «есть ли слова»
проверяет только АВТОзапуск (`maybe_review_vocabulary`). Принудительный путь —
`app.review_vocabulary()`; окно открывается даже без слов, и тогда само пишет
«Повторять нечего» (`VocabPanel._show_empty`: почему именно — из
`app._vocab_empty_note`: словарь пуст / слова ещё не созрели). Микрофон,
озвучка и правила захода — те же (`_open_vocab_panel` → `VocabularyController`
+ `VocabPanel`), второго пути нет.

Окно блока закрывается ДО открытия повторения (оба модальные — два
`grab_set` подряд не нужны). После захода с карты урок не взводится:
`_vocab_finished` взводит его только если об этом попросил запуск
(флаг `_arm_after_vocab`, ставится в `_after_vocab_review`).

Выключатель автоповторения — `VOCAB_REVIEW_ON_START` в `config.py`.

### Слова в разговоре (этап C — СДЕЛАНО)

К промпту Джейн добавляется ПОСЛЕДНИЙ необязательный блок
`🧠 WORDS FROM THE STUDENT'S OWN VOCABULARY`: 1–4 слова из её же словаря
(«ключ — key»). Модель может употребить ОДНО-ДВА слова по теме или спросить
так, чтобы ученик сам их сказал; список не зачитывать, опрос не устраивать.

- какие слова: `vocabulary.prompt_words(cards, limit)` — уровня 0–4
  (выученные 5 не берём), сначала нижние уровни, потом где больше промахов;
- собирает `ChatController._prompt_words()` из профиля ученика при КАЖДОМ
  ответе — слова живые, только что выученное сразу уходит из подсказок;
- выключатели: `VOCAB_IN_PROMPT` (весь этап C) и `VOCAB_PROMPT_LIMIT`;
  при выключенном или пустом списке промпт остаётся прежним байт-в-байт
  (правило §10 соблюдено — блок добавляется только если задан).

### Предзагрузка кусков озвучки (СДЕЛАНО)

Реплика Джейн режется на куски: по НАСТРОЕНИЮ (`mood.plan_reply`, чтобы лицо
меняло эмоцию вместе со звуком) и по ЯЗЫКУ (`split_by_language`, у русского
и английского разные голоса). Каждый кусок — отдельный запрос к edge-tts.

Раньше заранее качались только 1-й и 2-й куски, и на длинной реплике ученик
слышал провал **до 2.3 с** перед 4-м куском («Джейн задумалась»). Замер показал:
дело НЕ в переключении на русский голос (русский кусок качается столько же,
сколько английский), а в том, что дальние куски не успевали.

Теперь при `TTS_PREFETCH_ALL = True` качаются **все** куски сразу, пока звучит
первый (в среднем 1.0–1.2 с на кусок, а первый кусок звучит ~2 с). Одновременно
не больше 6 запросов (`_PREFETCH_SLOTS`). Замер на живой сети: реплика из
5 кусков (с двумя русскими) — **0.00 с** пауз между кусками, ничего не потеряно.

Отдельная забота — чтобы слово не пропало молча: `_play_segment` пробует
готовые байты → поток → повторную загрузку целиком (раньше при неудачной
предзагрузке кусок просто выбрасывался, и из смешанной фразы исчезало слово).
Смешанная фраза звучит ЦЕЛИКОМ: русское читает Светлана, английское — Ava.
Выключатель — `TTS_PREFETCH_ALL` в `config.py` (False = прежние «два вперёд»).

## 12. ГРАБЛИ (собраны по факту, не повторять!)

### Tk / CustomTkinter
1. **`tk.Text` `padx`/`pady` принимают ТОЛЬКО одно число** — отступы делать внешним `pack`.
2. **`window.after(0, fn)` из чужого потока** работает только при запущенном
   `mainloop` → использовать `controllers/dispatcher.py`.
3. **`pack` отдаёт место ПЕРВЫМ упакованным** — виджет, упакованный последним,
   на низком окне сжимается до нуля. Для полос над вводом — `pack(before=chat_view)`.
4. **`CTkTabview` вызывает `command` ТОЛЬКО по клику мыши** — программный `set()`
   вкладку не будит. Решение: подкласс `_Tabview` в `ui/app.py`.
5. **Свой метод `_draw` в наследнике `CTkFrame` конфликтует** с внутренним `_draw`
   customtkinter (падает при создании) → называть иначе (`_redraw_map`).
6. **У `CTkTextbox` НЕТ метода `count()`** — считать позицию каретки по внутреннему
   `tk.Text` (`self._field`), иначе вставка уходит «в конец».
7. **У текстового поля со `state="disabled"` команды `delete`/`insert` молча
   НИЧЕГО не делают** (без исключения) → писать через временное включение
   (`_replace_field_text`).
8. **Тултип поверх кнопки = мерцание**: курсор уходит на тултип → `<Leave>` →
   тултип скрывается → `<Enter>`… Ставить **под** виджетом.
9. **Tk рисует эмодзи одним тоном** → значки делать Pillow (`ui/emoji_render.py`).
10. **`ImageTk.PhotoImage` без сохранённой ссылки** — картинка исчезает.

### Анимация и производительность
11. **Шаг времени анимации считать по РЕАЛЬНЫМ часам**, а не «по кадру» —
    иначе при редких кадрах всё идёт вдвое медленнее.
12. **Не перерисовывать кадр, если он не изменился** (кэш по ключу: глаза+рот+сдвиг).
13. **`PhotoImage` создавать только при смене кадра** и кэшировать — иначе окно виснет.
14. **Эквалайзер: трогать только изменившиеся квадратики.** Перекраска всех 150
    за кадр ≈ 5.5 мс → лаги. Стало 2 вызова, 0.016 мс.
15. **Смена эмоции должна сбрасывать** моргание/взгляд/кивки, иначе состояние «замерзает».
16. **Пиксельные шрифты чёткие только на «родных» размерах** (проверять пиксельно).

### Python / Windows
17. **Tk не грузит шрифт по пути** — только установленные. Решение:
    `ctypes.windll.gdi32.AddFontResourceExW(path, 0x10 /*FR_PRIVATE*/, 0)`
    ДО создания окна (Tk читает список семейств один раз). Шрифт живёт
    только в процессе, система чистая; при закрытии — `RemoveFontResourceExW`.
17. **Параметр `time` в колбэке `audio_vad._audio_callback` перекрывал модуль `time`**
    → `AttributeError: no field 'monotonic'`. Называть `time_info`.
18. Печать кириллицы в cmd → `sys.stdout.reconfigure(encoding="utf-8")`.
19. Сохранение файла, открытого в просмотрщике → `OSError [Errno 22]`.
20. **Переводы строк:** большинство файлов CRLF. `write_local_file` пишет LF →
    править через Node с `\r\n` (в JS замена с `$` ломается → передавать `() => new`).
21. **Правки — ТОЧЕЧНЫЕ**: anchor-замена с проверкой, что якорь встречается РОВНО 1 раз;
    при промахе — `git checkout -- <файл>`.

### Тесты

### Повторение слов (этап B)

28. **Русский текст уходит в переводчик РАНЬШЕ любых проверок** (`_wants_translation`).
    Из-за этого «голосовые команды режима» и не работали: до разбора команд
    реплика не доходила. Любую проверку служебных фраз ставить ДО этой ветки.
29. **Модальное окно + микрофон дружат**: `grab_set` блокирует только клики по
    главному окну, запись и озвучка работают. Но открывать окно повторения
    можно только ПОСЛЕ теста уровня — `LevelTestPanel.ask` сам ждёт `wait_window`.
30. **Окно повторения в автотестах глушить**: `app.maybe_review_vocabulary = lambda: None`
    (иначе модальное окно ждёт ученика и тест висит). Вместе с ним глушить
    автозапуск урока: `app._arm_auto_lesson = lambda: False`.
31. **`window.after(ms, self.method)` запоминает метод в момент вызова** —
    подмена метода в тесте уже не сработает. Планировать через
    `lambda: self.method()` (на этом покраснел дым: урок начинался вместо
    проверки подсказки перевода).
32. **Модальное окно поверх модального** — не открывать: два `grab_set` подряд
    дают «залипшие» клики. В окне блока кнопка повторения сначала ЗАКРЫВАЕТ
    окно блока (`ask()` возвращает метку `VOCAB_RESULT`), и только потом
    `ui/app.py` открывает окно повторения.
33. **Заход повторения с карты не должен взводить урок** — иначе после
    проверки окна первая же реплика в чате начнёт занятие. Автозапуск
    взводится только из `_after_vocab_review` (флаг `_arm_after_vocab`).

### Озвучка (edge-tts)

42. **Первое соединение с edge-tts «холодное»**: 1-й запрос до 7 с (таймаут)
    или «No audio was received», 2-й ~3 с, 3-й ~5 с, дальше 1.0–1.3 с.
    Первая реплика урока приходится ровно на это — отсюда пауза после
    «Hello, Damil!». Лечится `tts.warmup_async()` при старте приложения.
43. **`_Prefetch.wait()` без таймаута = тишина до 26 с** (три попытки
    по 7 с). Ждать готовый кусок дольше `SEGMENT_WAIT_MAX` (1.5 с) нельзя:
    быстрее начать поток заново. И повтор загрузки делать только если
    следующая попытка укладывается в `DOWNLOAD_BUDGET`.
44. **Замерять озвучку без звука можно**: подменить `tts._sd` фейковым
    модулем с `OutputStream`, а в `write()` спать `len(arr)/24000` —
    тогда паузы между кусками измеряются как в жизни, а колонки не мешают.

### Английский язык обучения

45. **Синонимы ≠ разные значения слова.** Переводчик слова отдавал на «привет»
    три строки (hello / greeting / salutation), и все три становились
    карточками: ученик потом зубрил «a quick salutation before speaking».
    Правило: одна карточка на СМЫСЛ; со второй строки отбрасываем повторы и
    британские варианты (`translate.BRITISH_OR_FORMAL`), первая строка
    неприкосновенна.
46. **Слово карточки нормализуется**: «привет.» и «привет» — одно слово,
    иначе в словаре две карточки (`translate.normalize_word`).
47. **Без флага американского английского модель тянется к учебниковому
    регистру** («simple greetings», книжные слова) и к британским формам.
    Блок промпта + правила планировщика — единственное, что это держит.

### Скриншоты
26. Настоящий снимок — Pillow `ImageGrab` с учётом DPI:
    `ratio = shot.width / winfo_screenwidth()`, вырезать bbox `rootx/rooty/width/height`.
27. `capture_screen` пользователь отклонял — **спрашивать разрешение**.
34. **Окно Tk может оказаться ЗА чужим always-on-top окном** — тогда
    `ImageGrab` его не видит и снимок выходит пустым (проверено: красная
    заливка ловится, а `CTkToplevel` — нет). Для снимка поднимать окно:
    `win.attributes("-topmost", True); win.lift()`, после снимка снимать.
    В обычной работе это не нужно — на экране ученика окно видно.
35. **Проверять снимок числами**: считать в вырезанном прямоугольнике
    ожидаемые цвета (акцент #7C5CFF, белый текст) и сравнивать два похожих
    окна через `ImageChops` — иначе легко «показать» пустое место.
36. **Кэш картинок жетонов обязан включать НОМЕР точки** (`map_view`:
    ключ `(состояние, радиус, номер)`). Раньше ключ был `(состояние, радиус)`,
    и все жетоны одного состояния получали картинку ПЕРВОГО нарисованного —
    на карте все девять точек были под «2». Проверка: `tests/test_map_numbers.py`
    (9 разных картинок, ни одна не повторяется).
37. **`Array.join(функция)` НЕ подставляет результат** — `join` приводит
    аргумент к строке, и в файл уехал исходник функции (в `config.py` так
    затёрлись `TTS_RATE_EN/RU`; спас `git checkout -- config.py`). Функция
    работает только в `replace(pегулярка, fn)`. Простая замена строки:
    `s.split(a).join(b)` или `s.replace(a, b)` с ПРОСТОЙ строкой.
40. **id блоков и уроков обязаны быть уникальны во ВСЁМ плане**: учебные
    номера повторяются («1.1» есть в каждом блоке), а `ProgressMap` гасит
    повторы как дубликаты — в итоге читалась только ПЕРВАЯ локация (9 блоков,
    36 уроков вместо 117 и 468). Решение: id с префиксом (`forest/1.1`),
    короткий номер для экрана — в поле `code`. Исключение — «Пустыня»
    (простые id), иначе теряется прогресс в профиле ученика.
41. **Состояние локации нельзя считать через состояние блоков**: блок сам
    зависит от локации → бесконечная рекурсия. `is_location_completed`
    считает по УРОКАМ локации (`_location_lessons`).
39. **`llm_client.py` — файл с LF**, а не CRLF (как и `tests/*`): правка
    текстом с `\r\n` перемешала окончания строк. Перед правкой проверять
    фактические окончания (`git show HEAD:<файл>`), а после — что стиль файла
    не изменился. Промах виден в `git diff` как «весь файл изменён».
38. **Кусок озвучки нельзя выбрасывать молча**: если предзагрузка не удалась
    и сделать `continue`, из смешанной фразы пропадает слово (например,
    русское). Правильно — `_play_segment`: готовые байты → поток → повторная
    загрузка. Проверка: `tests/test_tts_prefetch.py` (раздел 3).
