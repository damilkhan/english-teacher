## 1. Что за проект

**EnglishTeacher** — локальный ИИ-преподаватель английского по имени **Verbot**.
Десктопное приложение на Python + Tkinter/CustomTkinter, работает на компьютере
ученика, говорит голосом, слушает микрофон, видит фото, ведёт уроки по карте
курса и повторяет слова по системе интервального повторения.

- **Ученик:** Дамиль, мужчина, уровень **A2** (из `level_tests` в профиле).
- **Главная цель — РАЗГОВОРНЫЙ английский (speaking)**, не письмо и не грамматика
  на бумаге. Любая фича оценивается по вопросу: «помогает ли она говорить?»
- Общение с учеником — **по-русски**, кратко, простыми словами. Он новичок в
  программировании: не объясняй ему то, что не спросили, и не сыпь терминами.

## 2. Правила, которые нельзя нарушать

1. **Числа только замеренные.** Не можешь замерить — скажи прямо «не замерял».
   Выдуманное число в этом проекте считается ложью.
2. **Ничего не объявлять работающим без прогона.** Если код менялся и тесты не
   запускались — так и пиши: «не проверено».
3. **Тесты — по одному файлу и ТОЛЬКО интерпретатором Python 3.10** (см. §3).
   Общий прогон всех 97 файлов — только по прямой просьбе ученика.
4. **Точечные правки.** Перед заменой проверь, что якорь встречается РОВНО один
   раз. Если правка не удалась — `git checkout -- <файл>`.
5. **Не менять код, не прочитав релевантные места.** Сначала читаешь функцию
   целиком, потом правишь.
6. **Никаких «улучшений заодно».** Одна задача — одна правка. Увидел рядом ещё
   проблему — скажи о ней отдельно, но не трогай.
7. **Перед коммитом смотреть `git diff` по своим файлам целиком.** Правка может
   попасть внутрь докстроки и ничего не сломать в тестах, но испортить смысл.
8. **Экономия контекста:** код читать куском ≤ 60–80 строк по якорю, большие
   выводы писать в файл (`logs/`), а не в чат.

## 5. Тесты

**В проекте 97 файлов `tests/test_*.py`.** Каждый запускается сам по себе,
печатает ✅/❌ по блокам и завершается кодом 1 при провале. Никакого pytest —
обычные скрипты.

Правила:
- гоняй **только те файлы, которые относятся к задаче**;
- часть тестов требует **живого окна Windows** (создают `EnglishTeacherApp`) —

- `tests/smoke_test.py` без `--gui` — быстрый, с `--gui` — поднимает окно и
  реально разговаривает с моделью (долго, не запускай без просьбы).

### Тесты, которые читают ИСХОДНЫЙ КОД, а не поведение
Эти файлы ищут подстроки в `.py`-файлах. Любая перестановка кода их ломает:
- `test_exam_lesson.py`, `test_lesson_summary_ui.py` — читают `ui/app.py`;
- `test_vocab_lines.py`, `test_vocab_request.py`, `test_quick_actions.py` — тоже
  смотрят исходники `ui/app.py` и `ui/panels/vocab_panel.py`;
- `smoke_test.py` — сверяет базу промпта с `gui.py` из коммита `b62c09a`
  **байт-в-байт**. Поэтому в промпт новые блоки можно добавлять **только
  необязательными и только в КОНЕЦ**, а блок `_words_block` обязан оставаться
  последним.

**Тексты интерфейса правятся ВМЕСТЕ с тестами** — тесты ищут русские подстроки
(«Повторить слова», «Дальше», «Готово»).

## 10. Главные грабли (собраны по факту)

**Tkinter / CustomTkinter**
- `tk.Text`: `padx`/`pady` — ОДНО число; `height` — в строках.
- `tkfont.Font.actual("ascent")` — ошибка, нужно `metrics("ascent")`.
- У CTk-виджетов `bind_all` ЗАПРЕЩЁН → `tk.Misc.bind_all(self, …)`.
- `pack(side="right")` отдаёт место ПЕРВОМУ упакованному.
- **`pack(before=widget)` падает, если `widget` ещё не упакован** («isn't
  packed»). Возвращая скрытую кнопку — только `pack(before=…)`, иначе она
  встанет левее и порядок ряда сломается.
- Эмодзи в облачке чата — это КАРТИНКА: в тексте 0 символов, в индексах
  `tk.Text` — 1. Раскраску считать по тексту РЕПЛИКИ (`_src_map`).
- `add_message` для реплики ученика возвращает `None`; метка — `chat._order[-1]`.

**Python / данные**
- `profile_store.load()` — это ПРОГРЕСС ученика, не профиль личности.
- `errors = 0` по умолчанию — подарок; при сбое разбора ставить `errors=None`.
- Печать эмодзи в cp1251 падает: в скриптах
  `sys.stdout.reconfigure(errors="replace")`; в `tts.py` есть `_say()`.

**Тесты**
- **Новый параметр роли или метода ломает ЗАГЛУШКИ в тестах** (`StubPlanner`,
  `blank_app`, подделка `App` в `test_vocab_request.py`). Добавляя параметр,
  сразу ищи подделки.
- В подделке `App` методы класса НЕ появляются сами — их привязывают руками
  (`App._open_words_after = EnglishTeacherApp._open_words_after`).
- `str.find` чувствителен к регистру.
- У `CTkButton` подпись встречается в `winfo_children` ДВАЖДЫ: считать
  `len(set(texts))`.
- Гонки: `busy` снимается В НАЧАЛЕ `_finish`, история пишется ПОСЛЕ — ждать
  `analyses`, а не `busy`.

**Промпт модели**
- Запрет с ПЕРЕЧНЕМ работает как подсказка (замерено): писать «никогда не
  приноси новую вещь САМ», а не список того, что нельзя.
- Модель НЕ считает свои вопросы: любой счёт передавать числом на каждом ходу.
- Новый блок промпта — **только за флагом** (образец: `_word_forms_block`).

**Урок**
- Зачёт задания приходит ДВАЖДЫ на одну реплику — нужен `already_credited`.
- Итог перед озвучкой: `_reply_in_flight` поднимать ПЕРЕД `finish()`.
- Конец урока: итог и фото ждут речи (`_deferred_finish`), `_speech_busy`
  ставить ДО потока.

**Данные**
- `.gitignore` держал `data/` целиком — новые `words_*.json` не попадали в git.
  Сейчас `data/*` + `!data/words_*.json`.

- Жёсткая JSON-схема ответа модели для глоссария (медленно).
- Сверка произношения с подсказкой **в обычном чате** (`PRON_CHECK_ENABLED = False`),
  но `pronunciation.py` НЕ удалять — окно слов сверку использует.
- Метка «задание сдано» от самой модели — модель плохо считает.
- Кнопка «не ошибка» в карте пробелов.
- Понижение уровня слова за промах.
- Тема урока по календарю — только по сдаче «Проверки» блока.
- Пустая карточка слов и объяснение ученику внутреннего алгоритма.

- Ограничение числа просьб слов в день.

- Сравнение текста ученика с картинкой; чек-лист «назвал / не назвал».

## 12. Как отвечать ученику

- **По-русски**, кратко, простыми словами. Он новичок — не «рефакторинг
  абстракции», а «переименовал функцию».
- **Сначала план, потом правки.** Перед изменением кода перечисли, что и где
  поменяешь, и дождись «приступай».
- После этапа: что сделано → какие тесты прогнаны (файл + результат) → что
  НЕ проверено вживую.
- Если что-то не получилось — сказать прямо, не замазывать.
- Не запускай задачи, которые долго работают без прогресса: пиши прогресс в файл.
